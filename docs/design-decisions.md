# 설계 판단

실제 인터뷰를 수행한 결과가 아니라 과제의 가상 대본을 읽고 정한 구현 가정입니다.

취소는 필수 요구 B-10을 따라 차감하지 않습니다. 선택 규정 문서의 늦은 취소 차감과 달라 고객 확인이 필요합니다. 만료일은 한국 시각으로 당일까지 포함하며, 이용권의 만료일 뒤 수업은 미리 예약할 수도 없습니다.

회원이 이용권을 여러 번 구매할 수 있어 상품과 구매 이력을 분리했습니다. 구매 횟수와 정가는 스냅샷으로 남깁니다. 잔여 횟수는 구매 횟수에서 완료와 노쇼를 빼서 구하고, 새 예약 가능 횟수는 여기에 예약 중인 횟수까지 제외해 구합니다.

이메일과 연락처 중복, 같은 회원과 트레이너의 같은 시각 중복 예약은 DB 제약으로 지킵니다. 타인의 이용권 연결은 이용권 ID와 회원 ID의 복합 외래 키와 백엔드 권한 검사로 막습니다. 유효기간과 근무 요일은 백엔드가 확인합니다. 예약 생성과 상태 변경은 같은 이용권 행을 먼저 잠급니다.

비밀번호는 bcrypt로 해시합니다. 세션 토큰도 DB에는 SHA-256 해시만 저장합니다. 원본 세션 토큰은 Next.js 서버가 HttpOnly 쿠키로 보관하며, 브라우저 응답 JSON에 토큰을 넣지 않습니다. 역할이나 활성 상태는 요청마다 현재 DB 값으로 확인합니다. 비밀번호 리셋과 계정 중지는 기존 세션을 무효화합니다.

운동 메모는 완료한 수업의 담당 트레이너나 관리자만 수정할 수 있습니다. 완료와 노쇼는 수업 시작 뒤에만 처리하고, 완료한 기록은 다시 다른 상태로 바꾸지 않습니다.

실제 서버 요청 16개와 두 Vercel 프록시의 로그인, 세션 유지, 로그아웃을 확인했습니다. DBeaver에서 직접 실행한 캡처와 휴대폰 확인은 별도 제출 전 점검 항목입니다.
